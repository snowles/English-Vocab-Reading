# H1 覆盖度矩阵（vocab-reading）

版本 **0.10.7** ｜ 更新 2026-11-12 ｜ 对应上架验收的 **H1 段：把输入空间切成有限维度，逐格确认有规则兜住**

## 0. 怎么读这张表

- **判定单位是「取值」，不是笛卡尔全积**：六个维度各自枚举有限取值，每个取值都必须能指到一条兜底规则。全积会炸成上万格且大部分无意义，按维逐格判才是可维护的做法。
- **规则必须可定位**：写成 `文件:函数`、`退出码` 或 `校验项名`。写「由模型判断」「应该会处理」一律不算兜底——那正是空格。
- **状态三档**：
  - ✅ 有规则，且有自动化证据（单测 / fixture 全流程）
  - 🟡 有规则，但只有人工验证，或样本没覆盖到全量规模
  - ❌ **空格**：没有规则，靠临场发挥。必须修，或明确裁定不做并给出拒绝规则。
- **边界**：本表只管「技能自身对输入的处理」；「模型识别得准不准」属关3 压测，不在这里。
- **退出码口径**（`scripts/run_pipeline.py`）：`0` 成功 / `2` 输入错误 / `3` 已标注拒绝 / `4` 校验失败 / `5` 内部错误 / `6` 已阻断未交付 / `7` 部分交付。

## 九、维护规则

1. **改了哪一层，就回填哪一格**：新增一个拒绝分支 = 某一格从 ❌/🟡 变 ✅；删掉一条校验 = 对应格立刻退回 ❌。
2. **新增维度取值必须同时给规则**，否则不许合入——这条比"多测几个样本"更有效，因为空格是设计出来的，不是测出来的。
3. **本表与 `references/testing.md` 的分工**：这里回答「有没有规则」，那里回答「跑了哪些用例」。两边都要更新，不能只改一边。
4. **状态为 🟡 的项不许在对外文案里说成"已支持"**。
